# 端侧 AI 周报：模型正在走出聊天框，进入设备与工作流

过去一周（2026 年 7 月 6 日至 12 日），端侧 AI 没有出现一场由大厂新品主导的发布潮，真正值得注意的变化来自开源工程：本地模型的安装和调用更像普通软件，Android 端开始具备 RAG、视觉和 API 服务等完整能力，而 Agent 也不再满足于“离线聊天”，开始连接工具、屏幕与真实设备。与其寻找一个轰动的新模型，不如观察这条逐渐清晰的产品路径——端侧 AI 正从推理 Demo 进入可组合的应用基础设施。

## 本地推理入口继续变简单

本周持续更新的 CSGLite，把模型下载、加载、对话和 OpenAI 兼容 API 收进一个跨平台二进制，并以 llama.cpp 运行 GGUF 模型。它还提供断点续传、Web UI、模型常驻，以及对编码 Agent 和第三方服务的配置入口。[S1] 这类项目的意义不只在于“又一个本地模型启动器”，而是将模型仓库、运行时和上层应用连接起来。开发者不再需要分别处理权重下载、服务进程和 API 适配，本地模型因此更容易成为现有工具链中的一个后端。

NativeLM Studio 则把方向推进到“本地 Agent 工作台”。项目本周仍在更新，使用 llama-cpp-python 执行 GGUF 推理，加入 MCP 工具发现、函数调用循环、本地 SQLite 会话，以及按需启用的网页检索。[S2] 值得注意的是，“本地优先”不等于完全断网：模型推理和聊天记录可以留在设备上，但搜索或外部 MCP 服务仍可能产生网络请求。产品在宣传隐私时，应把模型、数据、工具三个边界分别说明。

## Android 端开始追求完整产品能力

LlamaDroid 展示了一个更接近成品的 Android 路线。它以 Jetpack Compose 构建界面，经 JNI 接入 llama.cpp，并面向 Vulkan、OpenCL 与 NEON；功能不只包括流式对话和 GGUF 下载，还覆盖文档 RAG、视觉输入、语音、LoRA、推测解码、性能测试，以及可在局域网提供服务的 OpenAI 兼容 API。[S3] 项目目前关注度很低，成熟度仍需通过构建、真机兼容性和长期维护验证，但它列出的能力清单很有代表性：移动端竞争正在从“能否跑起来”，转向内存峰值、热管理、模型选择和系统集成是否足够顺滑。

这也解释了为什么 ONNX Runtime Mobile 与 MediaPipe 仍是重要基线。前者让 Android 与 iOS 应用按模型算子裁剪运行时，并可接入 NNAPI、Core ML、XNNPACK 等执行后端；后者提供覆盖文本、视觉与生成式任务的端侧方案入口。[S4][S5] 对团队而言，选择框架时不应只比较单次速度，还要同时评估包体、硬件覆盖、量化链路和算子回退，否则实验室里的加速可能在真实设备矩阵中迅速消失。

## Agent 开始走出应用沙盒

Aiden Hardware Demo 是本周更具想象力、也更需要谨慎看待的信号。它通过 HDMI-to-CSI 捕获目标设备画面，再以 USB HID 回传键鼠或触控操作；设备侧 Go Agent 负责截图、决策、语音与工具调用，不依赖 ADB、越狱或目标应用专用接口。[S6] 这为跨平台手机 Agent 提供了“外置硬件”思路，但项目明确仍是开发板实现，不是最终产品；视频输出条件、iOS AssistiveTouch、模型端点配置、提示注入与动作校验，都会决定它离日常可用还有多远。

## 本周判断

本周最清晰的趋势，是端侧 AI 的重心由单点推理转向系统拼装：运行时负责性能，兼容 API 负责接入，MCP 或函数调用负责行动，RAG 与多模态负责理解本地环境。短期内，真正能形成体验差异的未必是参数更大的模型，而是更可靠的模型生命周期管理、明确的数据边界，以及在不同价位设备上可复现的性能。接下来值得持续观察三件事：Android NPU 后端能否减少碎片化，小模型工具调用的成功率能否稳定，以及端侧 Agent 是否会形成可验证、可撤销的操作协议。

对准备做原型的开发者，本周这些项目也给出了一个务实顺序。第一步先选定单一任务和目标机型，用真实输入测量首字延迟、持续生成速度、峰值内存、耗电与温升，而不是只引用桌面端跑分。第二步再决定模型格式和运行时：若强调生成式对话与生态，GGUF 加 llama.cpp 的资料更丰富；若需要复用已有 ONNX 模型并覆盖多种硬件后端，则应先验证算子支持与回退路径。最后才加入 RAG、语音或 Agent 工具，并为每一次外部调用提供权限提示、超时、取消与操作日志。端侧的优势是低延迟、离线可用和数据可控，但这些优势只有在下载体积、模型更新、存储占用与失败恢复都被纳入产品设计后，才会真正转化为用户体验。
